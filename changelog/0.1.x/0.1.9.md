# 0.1.9 — 2026-09-20

## Added

- **`sessionMode: 'stateless'` on `createApp()`** — the HTTP session posture is declared in `src/` rather than left to a deployment's `MCP_SESSION_MODE`, which still wins whenever it carries a meaningful value. An install that sets no session mode now serves stateless instead of resolving the schema default `auto` to stateful.
- **`.github/workflows/codeql.yml`** — CodeQL static analysis on pushes to `main`, pull requests, and a weekly schedule.
- **Package metadata** — `package.json` declares `funding` (GitHub Sponsors, Buy Me a Coffee), and `.claude-plugin/plugin.json` carries a `$schema` reference and `keywords`.

## Changed

- **Tool arguments pass a pre-validation step** — a root key the client added is dropped, an undeclared key whose case-folded form names exactly one declared key is rewritten (`firstName` → `first_name`), and a JSON-stringified array is repaired and reparsed once, so `npi_get_provider`'s `npis` survives a client that serializes it. The advertised `inputSchema` is unchanged.
- **An out-of-schema argument is rejected as `InvalidParams` (`-32602`)**, not `ValidationError` (`-32007`), carrying `data.reason: "invalid_arguments"` and a schema-derived `Recovery:` hint; a required enum field left out renders as missing rather than as a wrong choice.
- **Tool error text closes with `(reason … · not retryable)`** whenever the error carries a `reason` or a boolean `retryable`. `structuredContent` is unchanged, so a test pinning `content[0].text` byte-exact should assert containment instead.
- **Upstream failures classify more precisely** — an NPPES 500 is `ServiceUnavailable` and retried where it previously failed on the first attempt, and a caller that disconnects mid-call is `RequestCancelled` (`-32011`), logged at `info` with no stack.
- **`npi_search_providers`'s `invalid_search_field` carries `thrownBy: 'service'`** — lint-only metadata marking the reason the NPPES service raises from the registry's `Errors[]`-on-200 envelope. Nothing on the wire changes.
- **The framework skill tree moved from `skills/` to `framework-skills/`** — plugin hosts auto-load a root `skills/`, which handed these development skills to every agent that installed the server. Repo layout only; the npm tarball and the `.mcpb` bundle are unaffected.
- **README leads with an overview and one reference block per tool and resource**, and states the NPPES and NUCC data attribution in its own section rather than a footer.
- **Issue forms auto-assign, accept blank issues, and route vulnerabilities to the private advisory form**; contributions are issues rather than pull requests.
- **`devcheck` gains a README version-badge parity check and an MCPB `user_config` wiring check**, and attributes `bun outdated` rows through `npm:` aliases back to the `package.json` key that declared them.
