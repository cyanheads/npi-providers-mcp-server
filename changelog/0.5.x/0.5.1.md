# 0.5.1 — 2026-11-19

## Added

- **`npi_search_providers` `name_role: "authorized_official"`:** `first_name`, `last_name`, and `name_search` match organizations' authorized officials, rows carry `authorizedOfficial` (`name`, `title`), and a search with no name fails as `official_name_required`. ([#45](https://github.com/cyanheads/npi-providers-mcp-server/issues/45))
- **`taxonomy_description` accepts a NUCC code or display name**, searching with that code's text (the registry's own wording for 21 codes, e.g. `363LP0808X` as `Psych/Mental Health`); an unknown or inactive code fails as `unresolved_specialty` before any request. ([#48](https://github.com/cyanheads/npi-providers-mcp-server/issues/48))
- **`unmatched_taxonomy_description`:** the registry's error 14 gets its own reason, with a recovery naming the code's classification to search, or a browse route for a classification-only code. ([#48](https://github.com/cyanheads/npi-providers-mcp-server/issues/48))
- **`matchedTaxonomy`** on search rows (rendered **Matched specialty**) names the non-primary taxonomy a row matched the specialty filter through. ([#44](https://github.com/cyanheads/npi-providers-mcp-server/issues/44))
- **`descriptionSource: "nucc"`** marks a taxonomy description filled from NUCC where the registry serves none, on search rows, `npi_get_provider`, and `npi://provider/{npi}`. ([#43](https://github.com/cyanheads/npi-providers-mcp-server/issues/43))
- **`npi_lookup_taxonomy` browse:** optional `classification` filter, and the first page lists `groupings` and, when the filters reach one grouping, its `classifications`, each with entry counts. ([#47](https://github.com/cyanheads/npi-providers-mcp-server/issues/47))

## Changed

- **Browse `grouping` filter:** also matches with "and" and "&" treated as the same whole word; every filter that matched before still matches.
- **NPPES error data:** a non-2xx response's upstream body no longer appears in the error (mcp-ts-core 0.13.22).
- **npi-providers-guide skill 1.1:** documents prefix taxonomy matching, `matchedTaxonomy`, code passthrough, and the postal-partitioning gaps.
- **Development tooling:** sync framework skills, scripts, and the changelog template to mcp-ts-core 0.13.22.

## Fixed

- **`postal_code`:** `ddddd-dddd` is sent as 9 digits, the location filter compares case-insensitively, and a registry rejection names the accepted forms. ([#42](https://github.com/cyanheads/npi-providers-mcp-server/issues/42))
- **Exact and lettered `postal_code` results:** a zero-row 2–4 or 6–8 digit code names its `*` prefix form, and a lettered code carries a notice that the registry returns only some of its records, routing to `city` without `postal_code` or `state`. ([#42](https://github.com/cyanheads/npi-providers-mcp-server/issues/42))
- **Specialty resolution:** lay terms (`skin`, `bone`, `lung`, `thyroid`, `prostate`, …), `GP`, `GI`, `ID`, `PT`, `OT`, `PCP`, `pain management`, and `nursing home` resolve to their professions, `OT` no longer reaches Otolaryngology, and `foot` and `hormone` prefer Podiatrist and Endocrinology. ([#46](https://github.com/cyanheads/npi-providers-mcp-server/issues/46))
- **"and" in specialty queries:** a query made only of "and" (`and`, `doctor and`) is rejected as naming no specialty, where 0.5.0 resolved it to Orthopaedic Foot and Ankle Surgery; "X and Y" spellings of NUCC "&" labels (Allergy and Immunology, Colon and Rectal Surgery) resolve to that entry.
