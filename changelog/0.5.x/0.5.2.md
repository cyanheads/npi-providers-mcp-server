# 0.5.2 — 2026-11-25

## Added

- **`npi_get_provider` accepts `npi` and `npi_numbers` for `npis`.** `tools/list` still advertises only `npis`, and an alias sent beside `npis` is rejected. ([#56](https://github.com/cyanheads/npi-providers-mcp-server/issues/56))

## Changed

- **`specialty`, and a `taxonomy_description` code or display name, return only rows holding a resolved code.** A classification-level code counts its whole classification, free text is never filtered, `matchedTaxonomy` names the first resolved code a row holds, and `resolvedTaxonomies` lists every later candidate sending the first's text at its level. A code newer than the bundled NUCC set counts only toward a classification-level resolved code whose classification its served description is (alone or before `, `), under that code's 4-character prefix. ([#51](https://github.com/cyanheads/npi-providers-mcp-server/issues/51))
- **npi-providers-guide skill 1.2:** documents the resolved-code filter and the exact continuation value.

## Fixed

- **A query token of one or two letters with no alias row matches only a whole word:** `im`, `ma`, `ed`, and `st` return `no_match` instead of an unrelated entry; `dr` is a stop word naming a physician; new alias rows `ob`, `em`, `at`, `mr`, `gy`. ([#49](https://github.com/cyanheads/npi-providers-mcp-server/issues/49))
- **`therapy` beside another term also matches the word "Therapist":** `physical therapy` and `occupational therapy` lead with the profession, not the assistant; new alias row `recreational`. ([#50](https://github.com/cyanheads/npi-providers-mcp-server/issues/50))
- **Dotted credentials in NUCC labels index as the joined word (`(M.D.)` → `md`), a regression from 0.4.0:** `Clinical Genetics (M.D.)` leads its own query again, and `Oral & Maxillofacial Surgery (D.M.D.)` resolves to `204E00000X`; `DMD` and `DDS` resolve to Dentist. ([#53](https://github.com/cyanheads/npi-providers-mcp-server/issues/53))
- **`continuationPostalCodes` lists the exact value first** for a 2–4 or 6–8 digit prefix (`6151*` → `6151`, `61510*`…`61519*`), reaching postcodes as long as the prefix. `postal_code <digits> matches only a postal code recorded with exactly those digits, so it splits no further`, and the empty-result hint for a value taken from `continuationPostalCodes` says that search ended its branch. ([#54](https://github.com/cyanheads/npi-providers-mcp-server/issues/54))
- **Registry and NUCC text in `content[]` is Markdown-escaped** so a CommonMark parse reads back what `structuredContent` carries; identifier codes and endpoint address types no longer render in brackets, and the terminal-window notice no longer echoes a non-numeric `postal_code`. ([#55](https://github.com/cyanheads/npi-providers-mcp-server/issues/55))
- **The location post-filter matches a 2–4 or 6–8 digit `postal_code` exactly,** as the registry does; only 5- and 9-digit requests keep the ZIP/ZIP+4 prefix tolerance. The empty-result notice for such a value says it matches only a practice address recorded as exactly that value, where it claimed none is recorded with it (false when another criterion, such as a specialty, emptied the search).
