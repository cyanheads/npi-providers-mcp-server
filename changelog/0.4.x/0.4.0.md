# 0.4.0 — 2026-09-24

## Added

- **`nextPage` and `continuationPostalCodes` on `npi_search_providers`** — a full page names the next `skip`/`limit`; the terminal window (`skip` 1000, `limit` 200) returns the `postal_code` prefixes that continue the search, empty when no postal split remains (a 5-digit ZIP, a full ZIP+4, or a non-numeric postal code) ([#12](https://github.com/cyanheads/npi-providers-mcp-server/issues/12)).
- **Trailing `*` on `postal_code` and `city`** — a 2–9 digit ZIP prefix (`98*`) or a city of 2+ characters (`SAN F*`) matches as a prefix in the location post-filter; any other `*` placement fails schema validation ([#12](https://github.com/cyanheads/npi-providers-mcp-server/issues/12)).
- **`matchedOtherName` on search rows** — `{ name, type? }` when the current name fails a requested `last_name`, `organization_name`, or wildcard `first_name` and an other (former, DBA, …) name satisfies it; the notice counts such rows. An exact `first_name` alone never marks a row ([#26](https://github.com/cyanheads/npi-providers-mcp-server/issues/26)).
- **`mixed_provider_criteria` error reason** — individual criteria (`first_name`, `last_name`, `name_search`, `provider_type: individual`) combined with organization criteria (`organization_name`, `provider_type: organization`) fail before any registry call, naming the fields on each side ([#30](https://github.com/cyanheads/npi-providers-mcp-server/issues/30)).
- **Credential-abbreviation aliases in `npi_lookup_taxonomy`** — `rn`, `np`, `pa`, `crna`, `lpn`, `lvn`, `emt` (Basic Emergency Medical Technician first), and `er` (Emergency Medicine) resolve to their NUCC entries ([#27](https://github.com/cyanheads/npi-providers-mcp-server/issues/27)).
- **Opt-in live NPPES integration suite** (`tests/integration/nppes-live.integration.test.ts`) — checks other-name marking and the postal-prefix continuation against the real registry; runs only with `NPPES_LIVE=1`.

## Changed

- **Stop-word-only queries fail instead of matching unrelated entries** — `physician`, `doctors`, `M.D.`, `specialist`, `providers` alone now fail with `no_match` (`npi_lookup_taxonomy`) or `unresolved_specialty` (`npi_search_providers` `specialty`) and a `browse` hint, naming the `Allopathic & Osteopathic Physicians` grouping for physician words ([#31](https://github.com/cyanheads/npi-providers-mcp-server/issues/31)).

## Fixed

- **Dotted abbreviations resolve as their undotted forms** — `P.A.`, `R.N.`, `N.P.` resolve as `pa`, `rn`, `np` rather than through one-letter tokens; a one-letter query token matches only a whole word ([#29](https://github.com/cyanheads/npi-providers-mcp-server/issues/29)).
- **Plural stop words are stripped like singular ones** — `heart doctors` resolves as `heart doctor`, and `physicians`, `MDs`, `specialists`, `providers` no longer act as required terms ([#32](https://github.com/cyanheads/npi-providers-mcp-server/issues/32)).
