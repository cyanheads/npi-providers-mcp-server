# 0.4.1 — 2026-10-08

## Changed

- **Error results carry the request id** — `data.requestId` is set and the error text ends with `request <id>` (mcp-ts-core 0.13.10, [cyanheads/mcp-ts-core#576](https://github.com/cyanheads/mcp-ts-core/issues/576)). Before, error results had no request id.
- **Arguments are repaired before validation**; each was rejected as `-32602` before:
  - `postal_code` sent as a JSON integer becomes its digits (0.13.9, [cyanheads/mcp-ts-core#487](https://github.com/cyanheads/mcp-ts-core/issues/487)).
  - `npis` sent as an integer, or an array of integers, becomes strings (0.13.14, [cyanheads/mcp-ts-core#570](https://github.com/cyanheads/mcp-ts-core/issues/570)).
  - A numeric string for `limit` or `skip` becomes a number (0.13.14, [cyanheads/mcp-ts-core#707](https://github.com/cyanheads/mcp-ts-core/issues/707)).
  - `null` at an optional argument is dropped (0.13.14, [cyanheads/mcp-ts-core#616](https://github.com/cyanheads/mcp-ts-core/issues/616)).
- **Declared recovery hints come from the framework's fill** (0.13.10, [cyanheads/mcp-ts-core#579](https://github.com/cyanheads/mcp-ts-core/issues/579)) — the handlers' and the NPPES service's `ctx.recoveryFor` forwards are removed. The hint text callers receive is unchanged.
- **`server.json` npm entries launch with `npx`** — both drop the `run start:stdio` / `run start:http` package arguments and change `runtimeHint` from `bun` to `npx`. The `streamable-http` entry adds `MCP_TRANSPORT_TYPE` with value `http`, so a registry client installing it starts HTTP (0.13.11, [cyanheads/mcp-ts-core#622](https://github.com/cyanheads/mcp-ts-core/issues/622)).
- **Dockerfile installs production dependencies in a `deps` stage on `$BUILDPLATFORM`**, cross-installing for the target architecture, so multi-arch builds no longer run Bun under QEMU (0.13.10). OTel peers install through `scripts/install-otel.ts` at the framework's declared ranges (0.13.10), and musl-only packages are pruned through `scripts/prune-musl-packages.ts` (0.13.11). `MCP_FORCE_CONSOLE_LOGGING` is removed (0.13.8); the base image moves from Bun 1.4.0 to 1.4.2.
- **`.github/workflows/codeql.yml` runs one job per language** (`actions`, `javascript-typescript`), each uploading under its `/language:` category.
- **Ignore files** — `.gitignore` ignores `.env*` except the example files; `.dockerignore` excludes `.env*` and the MCP registry token files; `.mcpbignore` adds `docs/idea.md`, `logs/`, `.cache/`, `coverage/`, and `tests/`.
- **Tooling scripts synced with the framework** — `devcheck`, `lint-mcp`, `lint-packaging` (Dockerfile build-platform, `server.json` launch-shape, `manifest.json` version, and `files` bundle-exclusion checks), `release-github` (`--check`), `check-skill-versions`, and `check-framework-antipatterns`. `devcheck.config.json` empties the `outdated` allowlist; `package.json` gains `audit:fix` and a `!dist/*.mcpb` entry in `files`.
- **`framework-skills/` synced to mcp-ts-core 0.13.14**, and `CLAUDE.md` / `AGENTS.md` refreshed from the framework template (context table, error-contract and `teardown` notes, command table, one-workflow CI note).
- **`README.md` and `.env.example`** — the tool sections are condensed, the MCP SDK and Bun badges read `^2.2.0` and `v1.4.2`, and the opt-in `LOG_TOOL_FAILURE_PAYLOADS` row is added to the env table. `.env.example` documents `MCP_REQUEST_STATE_KEY`, the `MCP_HTTP_RESUMABILITY*` variables, the `LOG_*` payload options, and the per-signal OTLP endpoints, and shows the `MCP_HTTP_HOST` default as `127.0.0.1`.
- **Tests** — `provider.resource.test.ts` adds a `resources/read` wire-level check of the `invalid_npi_format` hint, and `get-provider.tool.test.ts` asserts it through `runToolContract`.
