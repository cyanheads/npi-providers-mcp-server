# 0.2.0 — 2026-09-24

## Added

- **`npi_get_provider` `invalid[]` and `invalid_npi_format`** — each NPI's check digit (Luhn over `80840` + the NPI) is verified before any registry request; a failing NPI lands in `invalid[]` and is never looked up, and the call throws `invalid_npi_format` when every NPI fails. `npi://provider/{npi}` declares the same reason ([#13](https://github.com/cyanheads/npi-providers-mcp-server/issues/13)).
- **Endpoint fields `endpointDescription`, `useOtherDescription`, `contentOtherDescription`, and `line2`** on `npi_get_provider` and `npi://provider/{npi}`, rendered in the text output too ([#9](https://github.com/cyanheads/npi-providers-mcp-server/issues/9)).
- **`matchedLocation` on `npi_search_providers` rows** — the secondary practice location that satisfied the requested `city`/`state`/`postal_code`, present only when the primary practice location is elsewhere ([#18](https://github.com/cyanheads/npi-providers-mcp-server/issues/18)).

## Changed

- **Individual providers' `addresses` keep only `LOCATION` (practice) rows** — every other row on an NPI-1 record is withheld from `npi_get_provider` and `npi://provider/{npi}`: the `MAILING` row, which can be a home, with its phone and fax, and any row with a missing or unrecognized purpose. `LOCATION` rows keep their phone and fax; organizations keep every row ([#14](https://github.com/cyanheads/npi-providers-mcp-server/issues/14)).
- **`npi_search_providers` row `city`/`state`/`postalCode` come from the `LOCATION` address only** — absent when a record has none, never filled from a mailing row ([#14](https://github.com/cyanheads/npi-providers-mcp-server/issues/14)).
- **Location searches send `address_purpose=LOCATION`** — NPPES no longer matches the requested location against mailing addresses, so mailing-only rows stop taking page slots; the server-side location filter still runs ([#19](https://github.com/cyanheads/npi-providers-mcp-server/issues/19)).

## Fixed

- **A malformed NPPES 200 body surfaces as `ServiceUnavailable` after retry** — never a miss, a defaulted `status`/`enumeration_type`, or an invented identity. The body must carry a non-empty `Errors` array or a `results` array, and each result a 10-digit `number`, `enumeration_type` `NPI-1`/`NPI-2`, a `basic` object with `status` `A`/`D`, array fields holding only objects, and a non-blank string `code` on every taxonomy ([#15](https://github.com/cyanheads/npi-providers-mcp-server/issues/15)).
- **`npi_search_providers` keeps providers practicing at the requested location through a secondary practice location** — the location filter previously checked only the primary address and dropped them ([#18](https://github.com/cyanheads/npi-providers-mcp-server/issues/18)).
